# QXFRAME9A7C2 ESM / Component migration v13

## Scope

This increment migrates `Carousel` from the legacy `defineModule()` / `ComponentRegistry` implementation to a real ESM `class Carousel extends Component` source authority. Production `dist` remains generated by the frozen legacy build until the Rollup gate can be executed.

## Changes

- Added `src/components/carousel.js` as the canonical class implementation.
- `Carousel` imports canonical ESM owners directly: `DOM`, `Lifecycle`, `Scheduler`, `Config`, `Renderer`, `PointerSession`, `URLPolicy`, and `Utils`.
- `Carousel` inherits public `destroy()` and `updateOptions()` from `Component`; it does not duplicate either public lifecycle.
- Dynamic Carousel resources (frame/delay schedulers, item scope, pointer session, DOM listeners) are owned by the Component lifecycle through one internal resource scope.
- Added Carousel to `tools/manifests/esm-component-authority.json`.
- Added a temporary class module adapter in `src/compat/classComponentModules.js` so the remaining legacy consumers can continue resolving `ComponentRegistry.get('Carousel')` while receiving the new class authority.
- Removed `src/modules/carousel.js` from the executable source cutover dependency closure. It remains only for the frozen legacy production builder.
- `src/index.js` now exports `Carousel` directly from `src/components/carousel.js`.
- `src/components/index.js` now exports Carousel and its canonical enum constants.
- Expanded the frozen-dist class parity verifier to cover Carousel.

## Frozen behavior parity

The verifier compares the ESM class against an independent VM loaded from the frozen `dist/qxframe9a7c2.js`. Covered behavior includes:

- initial state and DOM projection;
- `goTo()`, `next()`, and `prev()`;
- callback sequence for `onChange`;
- active-item preservation across `setItems()`;
- `updateOptions()` projection changes;
- immutable `container` behavior;
- failed option transaction rollback;
- unknown option rejection;
- destroy cleanup and idempotence.

The frozen HOTFIX6 implementation contains an existing `clearPointer()` unresolved call when `disabled` is changed to `true` through `updateOptions()`. v13 intentionally preserves that behavior rather than fixing an unrelated legacy bug during structural migration.
