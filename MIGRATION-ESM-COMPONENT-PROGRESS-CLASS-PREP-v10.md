# QXFRAME9A7C2 ESM / Component Migration — v10

## Scope

This iteration remains **PRE-CUTOVER**. Production `dist` is still generated by the frozen legacy builder because the execution environment does not provide the declared Rollup binary. No kernel section is deleted and no public component authority is switched merely to bypass that gate.

The iteration advances the later Component/class migration preparation without changing current production behavior:

1. Adds `Progress extends Component` as the second concrete class candidate after `Result`.
2. Extends direct candidate parity coverage to Progress state, DOM, callbacks, option transactions and destruction.
3. Fixes the temporary `legacyFloatingUI.js` bridge so the source cutover graph can execute in a clean Node 22 ESM environment without an installed `@floating-ui/core` package.
4. Keeps CSS-only public modules such as Avatar/Badge/Card/Descriptions/Empty/Button out of the class migration: they have no instance lifecycle and should not receive artificial classes just to increase class count.

`Progress` inherits the canonical public lifecycle shells:

The concrete class only owns Progress-specific state/render behavior:


`setPercent()`, `setSuccessPercent()` and `setStatus()` update the canonical Component option transaction instead of maintaining a second options authority. A short-lived internal update-kind marker preserves the legacy callback rule: component methods render the new state but do not incorrectly emit the public `onUpdate` callback that belongs to `updateOptions()`.

## Frozen API behavior retained

The legacy Progress implementation contains code paths for numeric/object `size`, while the currently frozen public component contract accepts Progress `size` as a string. This migration does **not** silently widen that API contract. Structural migration remains behavior-equivalent; any contract correction must be a later explicit behavior/API change.

## Floating UI temporary bridge correction

`src/compat/legacyFloatingUI.js` embeds the frozen UMD payload until phase 30→35. In Node 22 ESM, CommonJS-like globals can make an embedded UMD wrapper select its CommonJS branch and attempt:

```text
require('@floating-ui/core')
```

A clean unpacked migration workspace has no `node_modules`, so that made the source cutover graph environment-dependent.

The compatibility file now locally shadows:

```text
exports
module
define
```

as undefined, forcing the embedded UMD payload onto its browser/global branch. This does not change production `dist`; it only makes the temporary bridge deterministic under ESM. The whole bridge is still scheduled for deletion in 30→35 when `@floating-ui/dom` becomes the real ESM dependency.
